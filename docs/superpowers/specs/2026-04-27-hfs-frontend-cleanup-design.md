# hfs_frontend Cleanup, SDK Upgrade, and Auth — Design

**Date:** 2026-04-27
**Repo:** `danghoangnhan/hfs_frontend` (branches per phase, see "Phasing")
**Author:** Daniel Du (`danghoangnhan`)
**Companion spec:** `2026-04-27-hfs-backend-fixes-design.md`

## Goals

1. Stop the project bleeding identity, dependency, and config drift before any feature lands.
2. Land on a current Expo SDK so future work isn't done on an EOL'd platform.
3. Implement the auth gate the codebase has been pretending to have, against the (now-fixed) backend contract.
4. Make release builds signable with a real keystore via env vars.
5. Replace the dead `expo publish` CI with a working `eas update` workflow.

## Non-goals

- Building any product feature (search, listings, messaging, save/like). Those are separate efforts.
- Adding TypeScript. The codebase is JS today; the cleanup keeps it JS. TS is a credible follow-up but doubles the SDK-upgrade scope.
- Theming / design system overhaul. The existing color palette + OpenSans stays.
- iOS native project. Android is committed; iOS is generated by `expo prebuild` if/when needed.

## Architecture (Phase 4 — Auth)

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ Login/Register  │────▶│   auth.slice     │◀────│  App.js (boot)  │
│   Profile       │     │ status, user,    │     │  loadTokens →   │
│   (UI)          │     │ tokens, error    │     │  fetchProfile   │
└────────┬────────┘     └─────────┬────────┘     └─────────────────┘
         │ dispatch                │ thunks
         ▼                         ▼
┌─────────────────────────────────────────────────┐
│  src/api/auth.js  ──▶  login()/register()/      │
│                        getProfile()/refresh()   │
│                        ▲                         │
│                        │ uses                    │
│                  src/api/client.js  ─── axios   │
│                  - baseURL from env             │
│                  - request:  Bearer interceptor │
│                  - response: 401 → refresh()    │
└────────────────────────────────────────────────┬┘
                                                 │
                          ┌──────────────────────┴────┐
                          │  src/services/secureStorage│
                          │  expo-secure-store wrapper │
                          └──────────────────────────────┘
```

### Components

**`src/api/client.js`** — single axios instance. Reads `process.env.EXPO_PUBLIC_API_URL` (default `http://10.0.2.2:8080/v1` for Android emulator). Two interceptors:

- *Request*: read access token from `secureStorage`, attach `Authorization: Bearer ...` if present.
- *Response*: on 401 with `error_key === "ErrInvalidToken"`, call `refresh()` once; if it succeeds, retry original request; if it fails, clear storage, dispatch `auth.logout()`, propagate error. A boolean flag prevents infinite refresh loops.

**`src/api/auth.js`** — typed (via JSDoc) wrappers around `client.js`:

```
login({email, password})       → {accessToken, refreshToken}
register({email, password, first_name, last_name})  → {userId}
getProfile()                   → {id, email, first_name, last_name, phone, role, avatar}
refresh({refreshToken})        → {accessToken, refreshToken}
logout()                       → void  (client-side only; no backend endpoint yet)
```

**`src/api/errors.js`** — maps backend `error_key` strings to user-facing English (later: i18n):

```
ErrUsernameOrPasswordInvalid → "Wrong email or password"
ErrEmailExisted              → "An account with this email already exists"
ErrInvalidToken              → (silent — handled by interceptor)
ErrWrongAuthHeader           → "Please sign in again"
ErrInternal                  → "Something went wrong. Please try again."
```

**`src/services/secureStorage.js`** — `expo-secure-store` is the right primitive (Keychain on iOS, EncryptedSharedPreferences on Android). API: `saveTokens(access, refresh)`, `loadTokens() → {access, refresh} | null`, `clearTokens()`. Single-key JSON blob under `hfs.auth.tokens`.

**`src/slices/auth.slice.js`** (renames `app.slice.js`):

```
state = {
  status: 'idle' | 'loading' | 'authed' | 'error',
  user: null | User,
  tokens: null | { access, refresh },
  error: null | string,
}
reducers/thunks: login, register, fetchProfile, logout, refreshTokens
```

The dead `export const { action } = appSlice` typo goes away in this rename.

**`src/navigator/Navigator.js`** — split into two stacks:

```
auth.status === 'authed' → DrawerNavigator (current Home/Tabs/Profile)
auth.status === 'idle' or 'error' → AuthStack (Login → Register)
auth.status === 'loading' → SplashView
```

`useEffect` on mount: dispatch a `bootstrap` thunk that loads tokens → if found, fetches profile → sets `authed` or `idle` based on result.

**`src/pages/Login/Login.js`** — email + password fields, error banner, "Don't have an account? Register" link. Uses `Button` from `src/components/Button`. Validates email format and non-empty password client-side. Submit dispatches `login` thunk.

**`src/pages/Register/Register.js`** — fields: email, password (with confirm), first_name, last_name. Same styling. After successful register, immediately call `login` so the user lands inside the app, not back at the login screen.

**`src/pages/Profile/Profile.js`** — rewrite to display `user.first_name`, `user.email`, `user.avatar` (if any), and a "Sign out" button that dispatches `logout` and clears storage.

## Data flow (Phase 4)

### Cold start

```
App.js mounts → bootstrap thunk
  → secureStorage.loadTokens()
    → null → status = 'idle' → AuthStack
    → tokens → axios.get('/profile')
                 → 200 → status = 'authed', user = data → DrawerNavigator
                 → 401 → refresh attempt
                          → ok → retry profile → authed
                          → fail → clearTokens → status = 'idle' → AuthStack
                 → other → status = 'error', error = message
```

### Login

```
LoginScreen submit → dispatch(login({email, password}))
  → api.login() → POST /v1/login
    → 200 → saveTokens(access, refresh)
            → fetchProfile() → user
            → status = 'authed' → navigation auto-switches via Navigator
    → 401 → mapError('ErrUsernameOrPasswordInvalid') → status = 'error', error = "Wrong email or password"
    → network → status = 'error', error = "No network. Try again."
```

## Mechanical fixes (Phase 1) — full list

1. Delete `package-lock.json`; keep `yarn.lock`. Add `package-lock.json` to `.gitignore`.
2. Move `expo-cli` and `jest` from `dependencies` → `devDependencies`. Drop `global` (unused). Drop the `braces ">=2.3.1"` pin (legacy npm-audit override; not needed).
3. Bump `axios ^0.24.0` → `^1.7.x` for known CVE patches.
4. Remove the `expo eject` script from `package.json` (eject removed from modern SDKs).
5. `src/slices/app.slice.js`: delete the broken `export const { action } = appSlice` line.
6. `src/navigator/Navigator.js`: add `dispatch` to the `useEffect` deps array (eslint-react-hooks).
7. `src/App.js`: wrap the `Promise.all` in try/catch; on failure, set `didLoad = true` anyway and log — don't hang on a blank `<View />` indefinitely.
8. `android/build.gradle`: drop `jcenter()` (sunset 2022). Keep `google()`, `mavenCentral()`, jitpack.
9. `README.md`: rewrite to describe `hfs_frontend` (HFS — Student Housing). Drop the upstream boilerplate banner and instructions.

These survive the SDK upgrade in phase 3 — they're not version-coupled.

## SDK upgrade (Phase 3) — strategy

**Target version**: latest stable as published on the `expo` npm tag at execution time. Expected to be SDK 52 or 53 given the calendar (Expo ships ~3 SDKs/year; SDK 50 was Q4 2023). Locked in by running `npm view expo dist-tags.latest` at the start of phase 3 and pinning that exact version across the spec.

Done in a git worktree (`../hfs_frontend.sdk-upgrade`) so the main worktree stays buildable. Sequence:

1. `npx expo install --fix` to align all `expo-*` packages to the target SDK.
2. `npx expo upgrade` (or `expo-doctor` + manual edits if upgrade is removed in target version).
3. Bump React Navigation to current major. This forces:
   - `headerMode="screen"` removed from `Stacks.js` (default in v6+).
   - `tabBarOptions={...}` → individual `screenOptions` per tab in `Tabs.js`.
   - `swipeEnabled={false}` removed (no longer a prop in v6).
4. Bump RN to whatever the target SDK pins.
5. `cd android && ./gradlew clean && cd .. && npx expo prebuild --clean` to regenerate native scaffolding (preserving local edits like keystore wiring will require care — do this *before* phase 5).
6. Manual smoke test: launch on Android emulator, navigate Home → Details → back → open drawer → Profile.

If the upgrade hits an unexpected breaking change, the worktree contains the damage; we abandon and try a smaller jump (e.g., 44 → 49 → latest).

## Release keystore (Phase 5)

`android/app/build.gradle` `signingConfigs.release`:

```groovy
release {
    storeFile     file(System.getenv("HFS_RELEASE_STORE_FILE") ?: "release.keystore.placeholder")
    storePassword System.getenv("HFS_RELEASE_STORE_PASSWORD") ?: ""
    keyAlias      System.getenv("HFS_RELEASE_KEY_ALIAS") ?: ""
    keyPassword   System.getenv("HFS_RELEASE_KEY_PASSWORD") ?: ""
}
buildTypes {
    release {
        signingConfig signingConfigs.release
        ...
    }
}
```

Daniel generates the keystore offline:
```
keytool -genkey -v -keystore release.keystore -alias hfs -keyalg RSA -keysize 2048 -validity 10000
```
…stores it outside the repo, sets the four env vars locally and as EAS secrets. The placeholder fallback lets `./gradlew assembleRelease` fail loudly with a clear message rather than silently using the debug keystore.

## CI (Phase 5)

`.github/workflows/main.yml` (rewritten):

```yaml
name: EAS Update
on:
  push:
    branches: [main]
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - uses: expo/expo-github-action@v8
        with:
          eas-version: latest
          token: ${{ secrets.EXPO_TOKEN }}
      - run: yarn install --frozen-lockfile
      - run: eas update --auto --non-interactive
```

Daniel creates an Expo account, runs `eas init`, adds `EXPO_TOKEN` to repo secrets. CodeQL workflow gets `init@v3` / `analyze@v3` bumps; rest unchanged.

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| SDK upgrade breaks something subtle (image loading, navigation gesture) | High | Worktree; keep main branch building; if upgrade is too painful, drop to a smaller jump |
| Backend `Validate()` PR not merged before phase 4 | Medium | Gate phase 4 start on backend PR merge; phases 1–3, 5 don't depend on it |
| `expo prebuild --clean` wipes our keystore wiring | Medium | Run prebuild *before* phase 5; commit the result; phase 5 layers keystore on top |
| Real device on LAN can't hit `10.0.2.2:8080` | Low | `EXPO_PUBLIC_API_URL` env override; documented in README |
| AWS leak gets exploited mid-project | Out of our hands | Escalate to AWS account owner; treat S3/`/upload` as broken until they rotate |
